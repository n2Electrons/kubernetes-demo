🔍 Kubernetes Debug Decision Tree

Interactive troubleshooting guide for Kubernetes issues

1 What type of issue are you experiencing?
2 What is the specific pod issue?
2 What is the network/service issue?
2 What type of resource issue?
2 What is the deployment issue?
2 What is the cluster issue?
2 What is the security/RBAC issue?
🔄 Fixing CrashLoopBackOff
Diagnosis Steps:

1. Check pod logs for error messages

2. Examine pod description for events

3. Verify container image and configuration

Step 1: Check Pod Logs

kubectl logs <pod-name> -n <namespace>
kubectl logs <pod-name> -n <namespace> --previous

Step 2: Describe Pod

kubectl describe pod <pod-name> -n <namespace>

Step 3: Common Fixes

  • Application Error: Fix code/configuration in container
  • Missing Dependencies: Update image or add init containers
  • Wrong Command/Args: Check container command and arguments
  • Resource Limits: Increase CPU/memory limits
  • Health Check Issues: Adjust readiness/liveness probes
⚠️ Quick Fix:
If container keeps crashing immediately, try disabling health checks temporarily:
kubectl patch deployment <name> -p '{"spec":{"template":{"spec":{"containers":[{"name":"<container>","livenessProbe":null}]}}}}'
⏳ Fixing Pending Pods

Step 1: Check Pod Events

kubectl describe pod <pod-name> -n <namespace>
kubectl get events --sort-by='.lastTimestamp' -n <namespace>

Step 2: Check Node Resources

kubectl top nodes
kubectl describe nodes

Common Causes & Solutions:

  • Insufficient Resources:
    kubectl get nodes --show-labels
    kubectl describe node <node-name>
  • Node Selector Issues: Check if pod can be scheduled on available nodes
  • Taints/Tolerations: Add tolerations or remove taints
  • PVC Binding: Check persistent volume claims
# Check PVC status
kubectl get pvc -n <namespace>
kubectl describe pvc <pvc-name> -n <namespace>
🖼️ Fixing ImagePullBackOff

Step 1: Verify Image Details

kubectl describe pod <pod-name> -n <namespace>

Common Fixes:

  • Wrong Image Name/Tag: Check spelling and tag existence
  • Private Registry: Add image pull secrets
  • Network Issues: Check connectivity to registry
  • Authentication: Verify registry credentials

Create Image Pull Secret:

kubectl create secret docker-registry regcred \
--docker-server=<registry-url> \
--docker-username=<username> \
--docker-password=<password> \
-n <namespace>

Test Image Pull Manually:

docker pull <image-name>:<tag>
# OR on node:
kubectl debug node/<node-name> -it --image=busybox
🚫 Fixing Service Unreachable Issues

Step 1: Check Service Configuration

kubectl get svc -n <namespace>
kubectl describe svc <service-name> -n <namespace>

Step 2: Verify Endpoints

kubectl get endpoints <service-name> -n <namespace>

Step 3: Check Pod Labels & Selectors

kubectl get pods -n <namespace> --show-labels
kubectl get svc <service-name> -n <namespace> -o yaml | grep selector -A 5

Step 4: Test Connectivity

# Port forward to test
kubectl port-forward svc/<service-name> 8080:80 -n <namespace>

# Test from within cluster
kubectl run debug-pod --image=busybox -it --rm -- sh
# Inside pod: wget -qO- <service-name>.<namespace>.svc.cluster.local
💡 Common Issues:
  • Service selector doesn't match pod labels
  • Wrong port configuration in service
  • No healthy endpoints (pods not ready)
  • Network policies blocking traffic
🔥 Fixing High CPU Usage

Step 1: Identify High CPU Consumers

kubectl top nodes
kubectl top pods --all-namespaces --sort-by=cpu
kubectl top pods -n <namespace> --sort-by=cpu

Step 2: Check Resource Limits

kubectl describe pod <pod-name> -n <namespace>
kubectl get pod <pod-name> -n <namespace> -o yaml | grep -A 10 resources

Solutions:

  • Increase CPU Limits:
kubectl patch deployment <name> -p '{"spec":{"template":{"spec":{"containers":[{"name":"<container>","resources":{"limits":{"cpu":"500m"}}}]}}}}'
  • Scale Horizontally:
kubectl scale deployment <name> --replicas=3 -n <namespace>
  • Enable HPA:
kubectl autoscale deployment <name> --cpu-percent=50 --min=1 --max=10 -n <namespace>
🚫 Fixing RBAC Permission Denied

Step 1: Identify Current User/Service Account

kubectl auth whoami
kubectl get sa -n <namespace>

Step 2: Check Permissions

kubectl auth can-i <verb> <resource> --as=<user> -n <namespace>
kubectl auth can-i get pods --as=system:serviceaccount:default:default

Step 3: Check Existing RBAC

kubectl get rolebindings,clusterrolebindings --all-namespaces
kubectl describe rolebinding <binding-name> -n <namespace>

Step 4: Create Missing Permissions

# Create role
kubectl create role pod-reader --verb=get,list --resource=pods -n <namespace>

# Create rolebinding
kubectl create rolebinding read-pods --role=pod-reader --user=<username> -n <namespace>
⚠️ Security Note:
Only grant minimum required permissions. Avoid using cluster-admin unless absolutely necessary.
